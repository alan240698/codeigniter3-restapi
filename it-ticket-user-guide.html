🎯 Tổng Quan Hệ Thống

IT Ticket System là hệ thống quản lý ticket tự động với Business Rules Engine. Sau khi setup xong, hệ thống sẽ tự động:

  • ✅ Phân loại ticket
  • ✅ Route ticket đến đúng team/người
  • ✅ Apply SLA policies
  • ✅ Enforce approval workflows
🎉 Kết quả cuối cùng: Khi user submit ticket → Hệ thống trả về JSON data chứa tất cả thông tin để dev xử lý tự động!

📋 SETUP WORKFLOW - ĐÚNG THỨ TỰ

Bước 1: Service Structure Tab (Foundation)

Mục đích: Tạo cấu trúc phân loại ticket

1. Service Groups (Nhóm dịch vụ) ↓ 2. Ticket Types (Loại ticket) ↓ 3. Issue Types (Vấn đề cụ thể)

📦 1.1. Service Groups (Nhóm Dịch Vụ)

Mục đích: Phân loại ticket theo department/lĩnh vực

Ví dụ thực tế:

Service Group Code Icon Mô tả
IT Infrastructure IT_INFRA 💻 Server, network, hardware
Software & Apps SOFTWARE 📱 Applications, licenses
HR Services HR 👥 Leave, payroll, onboarding
Facilities FACILITIES 🏢 Office, equipment, maintenance

📝 Tạo Service Group:

Name: IT Infrastructure
Code: IT_INFRA
Icon: 💻
Description: All IT infrastructure related services
Status: Active

🎫 1.2. Ticket Types (Loại Ticket)

Mục đích: Định nghĩa các loại yêu cầu trong mỗi Service Group

Ví dụ cho IT Infrastructure:

Ticket Type Code Service Group Mô tả
Access Request ACCESS_REQ IT Infrastructure VPN, system access
Hardware Issue HW_ISSUE IT Infrastructure Laptop, printer problems
Network Problem NET_ISSUE IT Infrastructure WiFi, internet issues

🔧 1.3. Issue Types (Vấn Đề Cụ Thể)

Mục đích: Chi tiết hóa vấn đề, có thể có sub-issues

📝 Ví dụ cho Access Request:

Ticket Type: Access Request ├── VPN Access (VPN_ACCESS) │ ├── New VPN Account (VPN_NEW) │ └── VPN Not Working (VPN_ISSUE) ├── Email Access (EMAIL_ACCESS) │ ├── New Email Account (EMAIL_NEW) │ └── Password Reset (EMAIL_RESET) └── System Access (SYS_ACCESS) ├── ERP Access (ERP_ACCESS) └── CRM Access (CRM_ACCESS)

📜 Bước 3: Rules Tab (Business Logic)

Mục đích: Định nghĩa rules tự động route ticket

3.1. Routing Rules (Tự động phân công)

📝 Ví dụ:

Rule Name Issue Type Assigned To Priority
VPN to L1 IT VPN Access L1 IT Support High
Network to L2 Network Problem L2 Network Team Critical

Kết quả: Khi user chọn "VPN Access" → Ticket tự động assign cho L1 IT Support!

3.2. Approval Rules (Phê duyệt)

Mục đích: Định nghĩa ai phải approve ticket trước khi xử lý

📝 Ví dụ thực tế:

Rule Name Issue Type Approver Condition
Manager Approval Leave Request Direct Manager Always
IT Manager Approval System Access IT Manager If > 3 systems
Director Approval Budget Request Director If amount > $5000 
Tạo Approval Rule:

Rule Name: Leave Needs Manager Approval
Issue Type: Leave Request
Approver Type: Direct Manager
Required: Yes
Order: 1
Status: Active
🎯 Kết quả: Leave request phải được manager approve trước khi L1 HR xử lý!
Flow: User submit → Manager approve → HR process → Closed

Ví dụ Multi-Level Approval:

Budget Request > $10,000: Step 1: Direct Manager (approve/reject) ↓ (if approved) Step 2: Department Head (approve/reject) ↓ (if approved) Step 3: Finance Director (approve/reject) ↓ (if approved) Step 4: CEO (final approval) ↓ Approved → Process payment

3.3. Level Rules (Escalation)

Mục đích: Tự động escalate ticket lên level cao hơn nếu không giải quyết kịp thời

📝 Ví dụ IT Support Escalation:

Level Team Time Limit Action
L1 L1 IT Support 4 hours First response & basic troubleshooting
L2 L2 Network Team 8 hours Advanced troubleshooting
L3 L3 Infrastructure 24 hours Expert-level resolution 
Tạo Level Rule:

Rule Name: IT Hardware Escalation
Issue Type: Hardware Issue

Level 1: L1 IT Support
  - Time Limit: 4 hours
  - Action: Diagnose and fix common issues

Level 2: L2 Network Team  
  - Time Limit: 8 hours
  - Action: Advanced hardware troubleshooting

Level 3: L3 Infrastructure
  - Time Limit: 24 hours
  - Action: Replace hardware or vendor escalation

Status: Active
⚠️ Auto-Escalation:
• Nếu L1 không resolve trong 4h → Tự động escalate lên L2
• Nếu L2 không resolve trong 8h → Tự động escalate lên L3
• Email notification gửi cho cả 2 teams (old + new)

Ví dụ HR Escalation:

Payroll Issue: L1: HR Team (2 hours) ↓ (if not resolved) L2: HR Manager (4 hours) ↓ (if not resolved) L3: HR Director (8 hours) ↓ (if still not resolved) Critical: Finance Director (immediate)

3.4. Custom Fields (Thông tin bổ sung)

Mục đích: Thu thập thông tin cụ thể cho từng loại ticket

📝 Ví dụ Custom Fields cho VPN Access:

Field Name Type Required Validation
VPN Username Text Yes Alphanumeric only
Department Dropdown Yes Sales, IT, HR, Finance
Access Duration Number No 1-365 days
Business Justification Textarea Yes Min 20 characters 
Tạo Custom Field:

Issue Type: VPN Access
Field Name: VPN Username
Field Type: Text
Required: Yes
Validation: Alphanumeric (a-z, A-Z, 0-9, ., _)
Placeholder: e.g., john.doe
Help Text: Enter your desired VPN username
Status: Active

Ví dụ Custom Fields cho Hardware Issue:

Field Name Type Purpose
Asset Tag Text Identify specific device
Device Type Dropdown Laptop, Desktop, Printer, Monitor
Problem Description Textarea Detailed issue description
Error Screenshot File Upload Visual proof of issue
💡 Smart Form: Khi user chọn "VPN Access" → Form tự động hiện các custom fields này!
Kết quả: Data được collect đầy đủ, agent không cần hỏi lại user!

Ví dụ Custom Fields cho Leave Request:

Field 1: Leave Type
  Type: Dropdown
  Options: Annual Leave, Sick Leave, Unpaid Leave
  Required: Yes

Field 2: Start Date
  Type: Date
  Required: Yes
  Validation: Must be future date

Field 3: End Date
  Type: Date
  Required: Yes
  Validation: Must be after Start Date

Field 4: Number of Days
  Type: Number (Auto-calculated)
  Formula: End Date - Start Date + 1

Field 5: Reason
  Type: Textarea
  Required: Yes
  Min Length: 10 characters

Field 6: Emergency Contact
  Type: Text
  Required: No
  Format: Phone number

💻 Dev Sử Dụng JSON Như Thế Nào?

1. Auto-Assignment

$assigned_team_id = $json['routing']['assigned_to']['id'];
$priority = $json['routing']['priority'];

DB::insert('tickets', [
    'assigned_team_id' => $assigned_team_id,
    'priority' => $priority
]);

2. SLA Tracking

$deadline = $json['sla']['resolution_deadline'];

SLATimer::create([
    'ticket_id' => $ticket_id,
    'resolution_deadline' => $deadline
]);

3. Auto Escalation

if (time() > strtotime($json['escalation']['l1_deadline'])) {
    $l2_team = $json['escalation']['l2_team'];
    Ticket::escalate($ticket_id, $l2_team, 2);
}

✅ CHECKLIST SETUP HOÀN CHỈNH

Service Structure

  • Tạo Service Groups (ít nhất 2-3)
  • Tạo Ticket Types cho mỗi Service Group (3-5 types)
  • Tạo Issue Types cho mỗi Ticket Type (5-10 issues)
  • Tạo Sub-Issues nếu cần

Teams

  • Tạo Support Teams (L1, L2, L3)
  • Add team members
  • Assign teams to Service Groups

Rules

  • Tạo Routing Rules (1 rule/issue type)
  • Tạo Approval Rules (cho sensitive requests)
  • Tạo Level Rules (cho escalation)
  • Tạo Custom Fields (cho data collection)
